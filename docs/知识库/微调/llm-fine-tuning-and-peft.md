# LLM 微调与 PEFT 落地

## 核心概念

### 1. 微调、RAG、Prompt 的边界

| 方案 | 解决什么 | 典型场景 |
| --- | --- | --- |
| Prompt / Few-shot | 指令表达、输出约束 | 需求变化快、样本少 |
| RAG | 外部知识注入、可溯源 | 知识频繁更新 |
| SFT | 稳定任务格式与行为 | JSON 抽取、工具调用格式、话术 |
| PEFT（LoRA/QLoRA） | 低成本任务适配 | 垂直任务、中小团队 |
| 继续预训练 | 领域语言分布 | 医疗/法律/代码底座 |
| DPO / RLHF | 偏好对齐 | 同一问题下好坏答案排序 |

**面试一句话**：微调改的是「稳定行为与输出分布」，不是实时知识库；知识变化优先 RAG。

### 2. SFT 与样本形态

监督微调用「输入 → 期望输出」对训练模型。常见形态：单轮问答、多轮对话、工具调用轨迹、拒答样本。样本要覆盖真实分布、边界与失败模式，不是越多越好。

### 3. LoRA 与 QLoRA

LoRA 冻结原权重 \(W\)，在部分线性层旁训练低秩增量 \( \Delta W = BA \)：

```text
y = W·x + B·A·x   # W 冻结，A、B 可训练
```

- **rank (r)**：表达能力；越大越强，也越容易过拟合、占显存。
- **QLoRA**：4-bit 量化 base + LoRA 训练，省显存；上线需再评估质量与延迟。

### 4. DPO 与 SFT 分工

SFT 学「标准答案长什么样」；DPO 学「多个候选里哪个更好」。有高质量偏好对时，DPO 往往比继续堆 SFT 更有效；RLHF 工程更重，面试知道取舍即可。

## 核心知识点

### 1. 何时微调 vs 何时不修

**适合**：格式长期稳定、调用量大、长 Prompt 成本高、有高质量标注与独立评测集、坏 case 可回流。

**不适合**：主要靠知识缺失、样本少且噪声大、需求剧烈变化、无评测集、试图绕过安全。

### 2. 数据集设计

```json
{"messages":[
  {"role":"system","content":"你是报销审核助手，只输出 JSON。"},
  {"role":"user","content":"报销 2300 元打车费，无发票。"},
  {"role":"assistant","content":"{\"decision\":\"reject\",\"reason\":\"缺少发票\"}"}
],"meta":{"source":"expense","label_version":"v1"}}
```

要点：去重、去泄漏、统一 Schema、难例与拒答、多样化问法、元数据（来源/版本/业务线）。

### 3. 训练流程与 LoRA 配置

```python
from peft import LoraConfig

# 中文注释：rank/alpha 决定 adapter 容量；target_modules 常见为 attention 的 q/v
lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    target_modules=["q_proj", "v_proj"],
    task_type="CAUSAL_LM",
)

training_args = {
    "learning_rate": 2e-4,          # 过大易遗忘，过小收敛慢
    "num_train_epochs": 3,          # 小数据集 epoch 过多易过拟合
    "per_device_train_batch_size": 4,
    "gradient_accumulation_steps": 8,
    "max_seq_length": 2048,
}
```

流程：基线评估 → 清洗切分 → 选 base → 训练 → 离线对比 base+prompt → 灰度 → 坏 case 回流。

### 4. 评估矩阵（多目标）

| 版本 | 任务指标 | JSON 可解析 | 安全违规 | P95 延迟 |
| --- | --- | --- | --- | --- |
| base+prompt | 82% | 91% | 0.8% | 1.2s |
| lora-v1 | 89% | 99% | 0.6% | 0.9s |

不能只看 loss；安全、成本、格式与业务指标一起权衡。

### 5. 过拟合、遗忘、泄漏

- **过拟合**：训练好、测试差、输出模板化 → 减 epoch/rank、增 dropout、补真实分布样本。
- **灾难性遗忘**：保留通用与安全评测集，控制学习率。
- **数据泄漏**：测试题进训练集 → 时间切分、近重复检测。

### 6. 上线：合并 vs 动态挂载

```text
请求 → 模型网关(model_alias) → base + adapter → 校验/安全 → 观测/回流
```

业务依赖**别名**而非产物路径；支持灰度、回滚、模型卡（数据版本、评估报告）。

### 7. 微调 + RAG

RAG 供事实，微调学引用方式、话术、query rewrite、拒答边界——二者常组合。

## 高频面试问题与标准答案

**Q1：什么时候选微调而不是继续改 Prompt？**  
当任务稳定、调用量大、格式/行为需高度一致，且有高质量 train/eval 时。先建 base+prompt 基线，证明微调有收益；知识类问题优先 RAG。

**Q2：微调能解决「不知道内部知识」吗？**  
不能默认可以。内部知识多变、需溯源用 RAG；微调学风格、格式、稳定决策。可组合：RAG 检索 + 微调组织答案。

**Q3：LoRA 原理？**  
冻结 W，训练低秩 BA 作为增量；省参、易多 adapter 版本管理；rank 与 target_modules 影响能力与过拟合。

**Q4：QLoRA 与 LoRA？**  
QLoRA 在量化 base 上训 LoRA，省显存；需额外验证质量、推理延迟与稳定性。

**Q5：数据集怎么建？**  
定义任务边界 → 真实样本覆盖常见/边界/失败 → 清洗脱敏去重 → train/valid/test 隔离（宜时间切分）→ Schema 一致。

**Q6：如何判断过拟合？**  
训练 loss 降而验证/测试不升、同义泛化差、模板化；查泄漏；减 epoch/rank、增正则、补样本。

**Q7：上线前评估什么？**  
任务指标、格式（JSON 可解析）、安全、工程（延迟/成本/失败率），对比 base+prompt，灰度看线上。

**Q8：微调后安全变差？**  
用安全集定位；补拒答/边界样本；控学习率与 epoch；**应用层**仍要校验、权限、审核，不能把安全全交给模型。

**Q9：DPO 解决什么？**  
同一输入下更好/更差回答的偏好对齐；SFT 已能答但风格/帮助性不稳时适用；依赖高质量偏好数据。

**Q10：微调为什么不是一次性？**  
分布、规则、底座会变；需坏 case 回流、评测回归、版本与灰度——否则短期指标好、长期漂移。

## 面试回答加分点

1. **决策框架**：Prompt/RAG/规则/微调按「知识 vs 行为」分流，不说「一律微调」。
2. **数据工程**：强调去重、脱敏、难例、拒答、时间切分；「微调不是数据垃圾桶，坏 case 先归因」。
3. **参数能解释**：learning rate、epoch、rank、target_modules 各影响什么，而非背 API。
4. **多目标上线**：任务指标与安全/成本冲突时如何取舍、为何不盲目上 lora-v2。
5. **网关与治理**：model_alias、灰度、回滚、模型卡、与观测/坏 case 闭环联动。
6. **200 条样本**：可试 LoRA 学格式，但不指望学复杂业务；无提升则停。
7. **应用层校验**：微调是概率行为，Schema/工具权限/人审仍必须。
8. **答题结构**：目标 → 为何微调 → 数据 → 训练 → 评估 → 上线 → 风险（过拟合/泄漏/安全）。
