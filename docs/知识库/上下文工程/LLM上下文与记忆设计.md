# LLM 上下文工程与记忆设计

## 核心概念

**上下文工程**是在有限 context window 内，选择、组织和压缩最有价值的信息，让模型稳定完成任务。不等于把所有历史对话塞给模型，而是围绕目标管理系统提示、用户输入、历史消息、工具结果、业务状态和外部记忆。

**记忆设计三类：**

| 类型 | 范围 | 典型内容 |
| --- | --- | --- |
| 短期记忆 | 当前会话 | 最近几轮对话、本轮工具结果 |
| 长期记忆 | 跨会话 | 用户偏好、稳定事实、任务状态 |
| 工作记忆 | 当前步骤 | 推理中间结果、待办、草稿 |

面试强调：**记忆是可检索、可更新、可删除的数据资产**，不是无限追加的聊天记录。

**与 RAG 的区别：** RAG 从外部知识库检索事实；上下文工程组织**当前任务所需的全部输入**——历史、状态、工具结果、记忆、系统规则。

```python
def build_context(user_msg: str, recent_msgs: list, memory: list) -> dict:
    # 中文注释：高置信记忆优先，控制条数与 token
    selected = [m for m in memory if m["score"] > 0.8][:5]
    return {
        "system": "按事实回答，不确定时说明缺少信息",
        "history": recent_msgs[-6:],  # 最近 N 轮
        "memory": selected,
        "user": user_msg,
    }
```

## 核心知识点

### 1. 上下文来源拆分

- **系统规则**：不可被用户覆盖的策略
- **用户问题**：当前轮输入
- **会话摘要**：早期对话压缩
- **结构化状态**：订单号、工单状态、任务进度
- **工具结果**：结构化 JSON，非原始 dump
- **长期记忆**：带分数、时间、来源的条目

### 2. Token 预算分配

为 system、用户问题、检索/记忆、模型输出预留固定比例。避免工具返回或冗长历史挤掉关键约束。

### 3. 保留与压缩策略

- **最近 K 轮**：原样保留
- **早期对话**：任务导向摘要（保留决策、约束、实体、待办）
- **精确字段**：金额、日期、权限用结构化存储，不单靠摘要

摘要原则：面向任务，非泛泛概括；摘要丢失的风险用结构化字段兜底。

### 4. 长期记忆写入规则

仅写入：稳定、可复用、用户允许、高置信的信息。


避免：模型猜测、临时偏好、错误事实永久污染。

### 5. 遗忘与隐私

支持过期、用户删除、撤销、脱敏。默认敏感数据不进长期记忆；必要时最小化保存。

### 6. 冲突优先级

系统规则 > 最新用户明确确认 > 长期记忆 > 旧摘要。冲突时宁可说明不确定，也不硬编。

### 7. 长上下文仍答错的原因

窗口变大 ≠ 有效利用。噪声过多、信息冲突、关键指令被淹没、错误事实排在前面，都会降低质量。**选择比堆叠更重要**。

### 8. Agent / 工作流中的上下文

- 不要把所有 Agent 对话广播给每个角色
- 工具结果只回传推理所需字段
- 工作流每节点只读结构化 `context_json` 中必要字段

### 9. 可复现性

记录每次送入模型的**最终上下文快照**（脱敏后），便于回放线上错误。

## 高频面试问题与标准答案

**1. 上下文工程核心是什么？**  
有限窗口内的信息治理：选择、压缩、权限与冲突处理，而非全量历史拼接。

**2. 短期、长期、工作记忆如何区分？**  
短期=会话最近信息；长期=跨会话稳定偏好/事实；工作记忆=当前推理中间态。写入长期需规则与授权。

**3. 为什么长上下文还会错？**  
噪声、冲突、排序不当、指令淹没。应筛选、摘要、结构化，并控制预算。

**4. 摘要丢信息怎么办？**  
任务导向摘要 + 结构化字段保存精确信息；关键约束双写（摘要+JSON 状态）。

**5. 如何避免记忆污染？**  
写入前置信度与授权；可删除可解释；不把模型猜测当事实；分库存「偏好」与「事实」。

**6. 上下文与 RAG 区别？**  
RAG 补外部知识库事实；上下文工程管当前任务全部输入的组织，含历史、状态、工具、记忆。

**7. 多轮对话如何裁剪？**  
滑动窗口保留最近轮 + 早期摘要 + 结构化状态；超预算优先砍早期非关键内容。

**8. 工具结果如何进上下文？**  
结构化、截断、Top-N；长日志先摘要；保留 `tool_call_id` 对应关系。

**9. 用户说「记住我喜欢简短回答」如何处理？**  
识别为偏好类记忆 → 置信度+确认 → 写入长期记忆表 → 后续 `build_context` 注入。

**10. 隐私合规要点？**  
最小化收集、脱敏、用户可见可删、按租户隔离、审计访问记录。

## 面试回答加分点

1. **三个关键词**：选择、压缩、治理——贯穿回答。
2. **画 token 预算表**，体现工程思维而非「尽量塞满 128K」。
3. **结合 Agent**：工具结果压缩、多 Agent 最小上下文分发（可引用多 Agent 文档）。
4. **反模式**：全量聊天历史拼接、无来源长期记忆、摘要替代精确金额字段。
5. **与 RAG 协作**：RAG 片段作为上下文一块，需标注 untrusted、防注入。
6. **一句话收束**：上下文工程是在预算内把对的信息在对的位置给模型；记忆是可治理的数据，不是聊天记录堆叠。
