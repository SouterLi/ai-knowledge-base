## 一、为什么这是高频考点

LLM 应用上线后，难点往往从“调通 API”变成控制成本、延迟和稳定性。面试常借此判断候选人是否具备生产化意识：能否量化成本、设计缓存、限制滥用，并在模型不可用或预算超限时保持核心功能可用。

## 二、核心概念

### 1. 成本拆解

LLM 应用成本不只包括生成模型费用，还包括：

- 输入 token：系统提示词、用户问题、历史对话、RAG 上下文。
- 输出 token：模型回答越长，成本和延迟越高。
- 辅助调用：Embedding、reranker、query rewrite、审核、函数调用。

回答要强调“先观测，再优化”，不能只说换便宜模型。

### 2. 缓存类型

- 精确缓存：相同请求直接返回结果，适合 FAQ、分类、抽取。
- 语义缓存：相似问题复用答案，需要 embedding 阈值。
- 检索缓存：缓存 RAG 召回或 rerank 结果。
- 前缀缓存：复用固定提示词、工具说明或长文档前缀。

缓存必须考虑权限、TTL、模型版本和 Prompt 版本，否则容易返回过期或越权答案。

### 3. 限流与预算

限流不是简单拒绝请求，而是用令牌桶、滑动窗口等算法，按用户、租户、接口、token 和模型等级治理。指标包括 RPM、TPM、并发数、日预算和重试次数。

## 三、关键设计步骤

1. 建立基线：记录 token、模型、耗时、命中率和费用。
2. 设定预算：按租户、功能和用户等级分配额度。
3. 控制输入：压缩历史对话，限制 RAG top_k。
4. 控制输出：设置 max_tokens，要求短答案，避免无限续写。
5. 增加缓存：先做精确缓存，再根据场景引入语义缓存。
6. 分级路由：简单任务用小模型，复杂任务升级到强模型。
7. 降级兜底：超预算时排队、异步处理或提示重试。

```python
def cache_key(model, prompt_version, user_scope, normalized_query):
    # 缓存键必须包含权限范围和版本，避免越权或旧提示词污染结果
    return f"{model}:{prompt_version}:{user_scope}:{normalized_query}"
```

## 四、常见面试问题

### 1. 如何降低一个 LLM 应用的线上成本？

先拆成本来源，再逐层优化：减少无效上下文、限制输出长度、缓存高频请求、简单任务用小模型、批处理 embedding，并用监控验证收益。

### 2. 语义缓存有什么风险？

相似不等于等价。风险包括意图不同、权限不同、数据过期、个性化条件丢失。解决方式是设置阈值，缓存键纳入权限和版本；高风险场景只缓存检索结果，不缓存最终答案。

### 3. 如何处理流量突增？

可以组合使用队列削峰、租户级限流、模型降级、关闭非核心链路、热点缓存和熔断。回答时要区分“保护系统”和“保护体验”：重要用户保留额度，低优先级任务异步化。

## 五、实践建议

- 不要只看平均成本，要看 P95/P99 长尾请求。
- 对每次模型调用记录业务场景，方便定位高成本功能。
- 重试必须有上限，并区分限流、超时和内容安全失败。
- 缓存命中率、过期率、误命中率要进入监控。
- 成本优化不能牺牲安全边界，权限过滤必须发生在缓存命中前。

## 六、一分钟总结

LLM 成本优化的核心是可观测、可控制、可降级。优秀答案应覆盖成本拆解、token 控制、缓存、限流、模型路由和监控闭环，体现从 Demo 到生产系统的工程化能力。
