## 你们是怎么做记忆管理的？

首先把最近K轮的用户问题和回答完整拼到prompt里去；

对于近期的热点记忆，我们首先会保存到缓存中，方便快速检索，超过一定时间未被查询的就删掉；

对于长期记忆，我们选择保存在RAG中，我们拿到用户的问题，先去RAG中检索相关记忆，并带上条件active=true，如果检索出来多条冲突记忆，就只保留最新的时间戳；

每次大模型生成回答，我们会对回答进行总结和提取，生成结构化记忆，存入RAG，带上时间戳，存入RAG之前，先检测RAG中是否已经存在相关记忆，如果含义一致，就合并记忆，如果含义冲突，就将旧记忆置为已过期并将新记忆存入；

另外，有一个定时任务定期清理与合并RAG中的记忆，根据记忆的召回频率，与用户的相关性，时效性进行打分，删除低分记忆；检索到相似记忆，进行合并；
### 如何防止RAG中保存的上下文记忆越来越多？

首先我们存储记忆的时候，保存的不是完整的上下文，而是经过LLM生成的结构化的记忆，每条记忆都附带元数据标签，只保留高价值记忆；
然后我们会对记忆进行定期的清理与合并，首先我们有一个记忆评分机制，根据访问频率，时效性，与用户的相关性进行评分，定期清理低分记忆；然后我们会合并相似记忆；最后对于长时间未命中切非长期事实的记忆进行删除；
最后是索引分层，对于最近几天频繁命中的记忆，我们会先保存在缓存中，过了一定时间后再放入RAG中。

### 如何防止RAG中保存的记忆出现冲突？

存储记忆时加入时间戳，当RAG检索到两个冲突的记忆时，让大模型自己判断已最新的信息为准；
或者在存储记忆时先检测是否存在已有相似记忆，如果含义相同，则进行合并，如果含义冲突，将旧记忆标为已废弃，检索时默认过滤废弃记忆。
如果出现无法准确判断时，请求用户进行澄清。
