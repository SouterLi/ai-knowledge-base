## 一、核心概念

上下文工程是指在有限 context window 内，选择、组织和压缩最有价值的信息，让模型稳定完成任务。它不等于把所有历史对话塞给模型，而是围绕目标管理系统提示词、用户输入、历史消息、工具结果、业务状态和外部记忆。

记忆设计通常分三类：短期记忆保存当前会话的最近信息；长期记忆保存跨会话的稳定偏好、事实和任务状态；工作记忆保存当前步骤正在推理的中间结果。面试中要强调：记忆是可检索、可更新、可删除的数据资产，不是无限追加的聊天记录。

## 二、关键步骤

1. 明确任务目标：先判断模型需要什么信息才能回答，而不是机械保留全部历史。
2. 拆分上下文来源：区分系统规则、用户问题、会话摘要、结构化状态、工具结果和长期记忆。
3. 设计保留策略：最近几轮直接保留，早期内容摘要化，关键事实结构化存储。
4. 控制 token 预算：为系统提示词、用户问题、检索信息和输出预留固定预算，避免重要信息被截断。
5. 建立记忆写入规则：只有稳定、可复用、用户允许保存的信息才进入长期记忆。
6. 设计遗忘机制：支持过期、撤销、用户删除和隐私脱敏。

示例：

```python
def build_context(user_msg, recent_msgs, memory):
    # 优先保留当前问题，再加入少量最近对话和高置信记忆
    selected_memory = [m for m in memory if m["score"] > 0.8]
    return {
        "system": "按事实回答，不确定时说明缺少信息",
        "history": recent_msgs[-6:],
        "memory": selected_memory[:5],
        "user": user_msg,
    }
```

## 三、常见问题

### 1. 为什么长上下文仍然会答错？

上下文窗口变长不代表模型会正确使用所有信息。噪声过多、信息冲突、排序不当和指令被淹没，都会降低回答质量。

### 2. 摘要会丢信息怎么办？

摘要要面向任务，而不是泛泛概括。可以保留决策、约束、用户偏好、待办状态和关键实体；对金额、日期、权限等精确信息用结构化字段保存。

### 3. 长期记忆如何避免污染？

写入前要做置信度判断和用户授权，避免把模型猜测、临时偏好或错误事实写入。高风险记忆应可回滚、可解释、可删除。

### 4. 上下文和 RAG 的区别是什么？

RAG 侧重从外部知识库检索事实；上下文工程更关注把当前任务所需的所有信息组织进模型输入，包括历史、状态、工具结果和记忆。

## 四、实践建议

- 不要把聊天历史完整拼接到提示词中，要先做筛选和压缩。
- 对“用户偏好”和“事实状态”分库存储，避免混淆。
- 长期记忆写入应有来源、时间、置信度和删除入口。
- 对冲突信息设置优先级：系统规则高于用户历史，最新确认高于旧摘要。
- 记录每次最终上下文，便于复现模型错误。
- 对隐私数据默认不写入长期记忆，必要时做脱敏和最小化保存。

## 五、一分钟总结

上下文工程的核心是“有限窗口内的信息治理”。优秀设计会区分短期记忆、长期记忆和工作记忆，按任务选择信息，按预算压缩信息，按权限保存信息。面试回答应突出三个关键词：选择、压缩、治理。能讲清 token 预算、摘要策略、记忆污染、隐私删除和冲突优先级，通常就是加分答案。
