# LLM 应用评估与可观测性

## 主题选择记录

- **主题**：LLM 应用评估与可观测性（LLMOps）
- **分类**：AI 应用开发 / LLMOps
- **仓库去重**：RAG 文档含检索指标；本主题覆盖**全链路评测与线上观测**
- **适用岗位**：AI 应用开发、平台工程师

## 核心概念

模型、Prompt、知识库、用户分布都会变，**上线≠稳定**。评估回答「效果够不够」；可观测性回答「线上发生了什么」——二者闭环才能迭代。

评估不能只看「读起来不错」：要拆**检索、生成、工具、业务、工程**指标。可观测性要为排障服务：用 `request_id` 串联检索 → LLM → 工具，且日志脱敏。

## 核心知识点

### 1. 质量指标

- **正确性 / 任务成功率**  
- **Faithfulness**：是否忠于给定上下文  
- **Answer Relevance**：是否答非所问  
- **格式合规率**（JSON/字段）  
- **工具选择率、参数准确率**（Agent）

### 2. 工程与业务指标

TTFT、端到端延迟、超时率；input/output token、单次成本；错误率、重试率、限流次数；采纳率、追问率、转人工率。

### 3. 评测集建设

来源：高频问、边界问、历史失败、安全样本、对抗样本。每条含：问题、参考答案或要点、`expected_facts`、`forbidden`、场景标签。

```python
case = {
    "id": "pwd_reset_01",
    "question": "企业账号怎么重置密码？",
    "expected_facts": ["账号中心", "手机验证", "设置新密码"],
    "forbidden": ["联系 DBA 改库"],
    "tags": ["账号", "高频"],
}
```

### 4. 自动化 + 人工

改 Prompt/模型/检索/工具 → CI 跑回归。LLM-as-Judge 适合规模化初筛；**关键业务必须人工或规则**（金额、合规、医疗）。

### 5. 幻觉排查路径

上下文有没有金句？没有 → 检索/数据；有还编 → Prompt 约束、模型能力、拒答策略、输出校验。

### 6. 线上观测字段

`request_id, user_id, prompt_version, model, retrieval_ids, tool_calls, latency, tokens, error, feedback`。

### 7. 问题回流

差评、无答案、高成本、工具失败 → 进入评测集与告警看板。

### 8. 与 RAG/Agent 的评测差异

RAG 加强 Recall@K、Citation；Agent 加强步骤成功率、工具准确率、安全违规率。

## 高频面试问题与标准答案

### 1. 评估和可观测性有什么区别？

评估是离线或批量的「打分」，用来发版决策；可观测性是实时的「记录与告警」，用来发现和定位线上退化。我会两者都做，否则不知道变好还是变坏，也不知道为什么坏。

### 2. 如何证明一次 Prompt 改动有效？

同一评测集上对比：准确率、faithfulness、格式通过率、拒答是否正确，再看 P95 延迟和 token。改动要有版本号和 changelog，避免无法回滚。

### 3. 离线过了线上还差，为什么？

评测集覆盖不够：真实口语、多轮、长尾、恶意输入没进去。解决是定期从日志分层采样补 case，并按场景（客服/代码/合同）分开评。

### 4. 能用 LLM 当裁判吗？

可以作辅助，但不能唯一标准。裁判模型有偏好，标准不清时评分漂移。金融、医疗、权限我会加规则和人工抽检。

### 5. 如何排查幻觉？

先看 trace 里检索片段是否包含答案要点。不包含就查数据和检索；包含还编就查 grounded Prompt、temperature、是否该拒答。别一上来换大模型。

### 6. Agent 怎么评估？

除了最终回复，还要看工具选对没、参数对不对、步数是否爆炸、有没有越权调用。用任务集回放，统计成功率和安全违规率。

### 7. 线上日志记什么才不爆隐私？

记 ID 和摘要，不记完整身份证、卡号；Prompt 可 hash 或截断。需要深度排障时用权限受控的临时提升日志级别。

### 8. 成本异常怎么从观测发现？

按场景聚合 token：哪个接口 input 均值突增、谁触发了 10 次工具重试。设预算告警，而不只是月末看账单。

### 9. 用户点踩的数据怎么用？

和 request_id 关联，进入回流队列；每周归类是检索、生成还是产品逻辑问题，优先补高频失败 case 进评测集。

### 10. 上线门槛你会定哪些？

核心场景评测集通过率不低于基线、faithfulness 达标、P95 延迟可接受、无 P0 安全回归、可观测和告警就绪。Demo 和标准生产不一样，面试里说出来是加分项。
